# КОНТРАКТ v4 — подключение существующей Yandex Cloud Function

Формы `index.html` и `#contact-modal` теперь направляют данные на публичный HTTPS endpoint функции **zayavka**. В архиве есть **обновлённый код самой функции**: `cloud-function/index.js`. Функция пользователя в Yandex Cloud сама по себе НЕ была изменена: её новую версию необходимо опубликовать вручную.

## 1. Заменить index.js в существующей функции

Yandex Cloud → Cloud Functions → zayavka → Редактор → index.js. Вставьте код из `cloud-function/index.js`, оставьте среду Node.js 22, точку входа `index.handler`, опубликуйте новую версию.

Сохраните переменные окружения `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ALLOWED_ORIGIN`; секреты не вставлять в сайт или архив.

## 2. Указать ALLOWED_ORIGIN

Функция пропускает запросы только с точного Origin. Для тестирования локально при запуске `python3 -m http.server 8080` добавьте к существующим разрешённым источникам:

`http://localhost:8080,http://127.0.0.1:8080`

Если сайт размещён в интернете, добавьте точный origin сайта, например `https://example.ru,https://www.example.ru`. Укажите фактический домен, не example.ru и не `*`. Origins разделяются запятой БЕЗ слеша после домена. `file://` не поддерживается — откройте сайт через локальный HTTP-сервер.

## 3. Проверка (только вымышленные данные)

1. Убедитесь, что бот добавлен в нужную Telegram-группу и может отправлять сообщения.
2. Откройте сайт через `http://localhost:8080/` или опубликованный домен, разрешённый в ALLOWED_ORIGIN.
3. Нажмите «Оставить заявку» в карточке «Водители BCDE».
4. Введите тестовые ФИО/телефон/возраст 18–64, подтвердите согласие, отправьте.
5. Проверьте сообщение в Telegram: ФИО, телефон, возраст, вакансия, UTM/yclid (если присутствуют).

Нельзя проверять отправку реальными персональными данными до публикации политики и выполнения требований к их обработке. `privacy.html` всё ещё заглушка и должна быть заменена.

## Перед публичным запуском

- Подтвердить сведения об организации, финансовые и возрастные условия для вакансий.
- Разместить действующую политику конфиденциальности и текст согласия.
- Настроить защиту публичной формы от ботов: текущий Origin/CORS + honeypot **не равнозначны серверному rate-limit**. При необходимости добавьте Yandex SmartCaptcha и проверку токена на сервере, а также лимиты запросов.
- Сроки, доступы и удаление персональных данных в Telegram-группе необходимо определить и ограничить круг менеджеров.
- Сверить HTTPS URL функции в `js/main.js` со своей консолью Yandex Cloud; сайт не разворачивался и реальная отправка не проверялась.
- При переносе формы на Tilda обеспечить передачу JSON с аналогичными полями или доработать функцию для формата Tilda: готовый endpoint сейчас ожидает JSON, не form-urlencoded.

## Формат JSON

`full_name`, `phone`, `age`, `vacancy`, `consent: true`, `website: ''`, `source_url`, необязательные `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `yclid`.

## Структура

- `index.html`, `privacy.html` — сайт и временная юридическая страница.
- `js/main.js` — отправка с обеих форм и валидация клиента.
- `cloud-function/index.js` — готовый код обновления существующей Yandex Cloud Function.
- `tilda/` — исходные фрагменты для последующего переноса, см. `tilda/README.md`.
